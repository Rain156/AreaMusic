# AreaMusic Forge 1.20.1 设计说明

## 目标

AreaMusic 为 Forge 1.20.1 提供由服务端管理的长方体音乐区域。玩家进入区域时，客户端从游戏根目录的 `AreaMusic` 文件夹播放本地音乐；离开全部区域时淡出；从一个区域进入另一个区域时交叉淡化。

首版必须满足以下条件：

- 单人游戏与多人游戏使用同一套服务端判定、网络同步和客户端播放流程。
- 服务端与每位客户端分别放置同名音频文件，不通过网络传输音频内容。
- 支持 OGG、MP3、WAV 和 FLAC，解码器可继续扩展。
- `/areamusic reload` 同时重载服务端音乐索引、区域 JSON，并通知在线客户端重扫本地音乐目录。
- 区域按存档隔离，JSON 可由管理员直接编辑和调试。

首版不提供音频下载、资源包生成或可视化选区工具。游戏内仅在原版“音乐和声音选项”页面提供 AreaMusic 独立音量滑块。

## 已确认的产品决策

- 创建区域使用一条带完整坐标的命令。
- 重叠区域先比较显式 `priority`；相同时选择体积更小的区域；仍相同时按区域 ID 排序，确保结果稳定。
- 区域切换使用真正的同步交叉淡化，默认持续 2 秒。
- 音轨默认循环，可在每个区域的 JSON 中关闭循环。
- 同一 MusicID 的相邻区域不重启音轨，只平滑调整播放参数。
- 管理命令要求权限等级 2。
- 客户端缺少文件或无法解码时只向该玩家提示并保持静音，不将玩家踢出服务器。

## 文件布局

模组首次启动时创建：

```text
<gameDir>/
  AreaMusic/
    village/day.mp3
  config/
    areamusic/
      <saveId>/
        village_square.json
```

`saveId` 由当前世界存储目录名生成：保留便于识别的安全名称，并附加原始目录名的 8 位 SHA-256 摘要以避免清理名称导致碰撞。单人存档目录在同一游戏根目录内唯一；独立服务器拥有自己的游戏根目录，因此每个存档都得到独立区域目录。

MusicID 是 `AreaMusic` 下包含扩展名的相对路径，统一使用 `/` 分隔，例如 `village/day.mp3`。扫描递归处理子目录，忽略不支持的扩展名、目录和逃逸根目录的符号链接。ID 保留 Unicode 和大小写；扫描时拒绝仅大小写不同的冲突项，避免 Windows 与 Linux 行为不一致。

## 区域 JSON

文件名是不含扩展名的区域 ID。区域 ID 必须匹配 `[a-z0-9][a-z0-9_-]{0,63}`，从而可以安全地作为命令参数和文件名。

```json
{
  "schemaVersion": 1,
  "dimension": "minecraft:overworld",
  "pos1": { "x": 0, "y": 64, "z": 0 },
  "pos2": { "x": 20, "y": 80, "z": 20 },
  "musicId": "village/day.mp3",
  "priority": 0,
  "volume": 1.0,
  "loop": true,
  "fadeInMs": 2000,
  "fadeOutMs": 2000
}
```

两个端点的顺序不限。加载时计算每个轴的最小值和最大值，边界方块属于区域。`volume` 范围为 0.0 到 1.0，淡化时长范围为 0 到 60000 毫秒。维度必须是有效资源位置。JSON 使用 UTF-8 和格式化输出。

## 命令

```text
/areamusic create <areaId> <x1> <y1> <z1> <x2> <y2> <z2> <musicId>
/areamusic reload
```

坐标接受 Brigadier 的绝对坐标、`~` 相对坐标和 `^` 局部坐标。区域绑定命令源当前所在维度。MusicID 参数使用服务端音乐索引补全；包含空格时使用 Brigadier 引号形式。

`create` 执行以下验证：区域 ID 合法且尚不存在、坐标位于世界构建范围、MusicID 存在于服务端索引。成功后通过临时文件加原子移动写入 JSON，立即替换服务端区域快照并重新判定玩家，无需额外执行 `reload`。默认值为 `priority: 0`、`volume: 1.0`、`loop: true`、淡入淡出各 2000 毫秒。

`reload` 先构建新的音乐索引与区域快照，完成全部校验后一次性替换当前状态。任一 JSON 语法错误、字段错误、重复 ID 或缺失服务端音频都会导致本次区域重载失败并保留上一份有效快照。命令结果列出音频数、区域数以及具体错误文件。成功后递增配置版本、通知客户端重扫，并重新判定所有在线玩家。

## 服务端组件

### MusicLibrary

扫描服务端 `AreaMusic` 目录，建立不可变的 `MusicID -> Path` 快照并提供命令补全。扫描和解析在服务器线程之外完成，快照替换回到服务器线程执行。

### AreaRepository

负责存档目录解析、JSON 读写、模式版本检查和原子快照替换。运行时区域对象包含已经规范化的边界和预计算体积，不在玩家判定热路径中访问磁盘。

### AreaResolver

服务器记录每位玩家上次检查的维度、方块坐标和配置版本。三者均未变化时跳过判定；变化时查找所有包含玩家的区域，并按以下顺序选择：

1. `priority` 降序；
2. 区域体积升序；
3. 区域 ID 字典序升序。

只有有效区域或其播放参数变化时才发送新状态。玩家离开所有区域时发送空状态；登录、重生、跨维度和重载后强制同步。

### AreaMusicNetwork

使用 Forge `SimpleChannel` 和严格协议版本。服务端到客户端的状态包包含配置版本、可选区域 ID、MusicID、音量、循环、淡入和淡出参数。重载包要求客户端重扫本地目录；音频字节永不进入网络包。

## 客户端音频

### ClientMusicLibrary

启动、连接服务器以及收到成功重载通知时扫描本地 `AreaMusic`。它采用与服务端相同的 MusicID 规范化和冲突检查。扫描失败保留上一份有效本地索引。

### DecoderRegistry

使用成熟的 Java Sound 解码服务提供器处理 OGG、MP3、WAV 和 FLAC，不手写压缩格式解码器。各解码器输出统一采样格式的 PCM 流；不支持的通道布局、损坏文件和转换失败会返回结构化错误。

### PcmAudioMixer

一个客户端专用守护线程拥有 `SourceDataLine`，从命令队列接收播放状态。解码在有界缓冲中流式进行，不把整首音乐读入内存。混音器将活跃音轨转换为统一 PCM 格式、应用淡化包络、区域音量、Minecraft 主音量以及 AreaMusic 独立音量，再进行饱和混音。原版“音乐”音量不参与 AreaMusic 的增益计算。

### 独立音量

原版“音乐和声音选项”页面显示一个 `AreaMusic 音量` 滑块，默认值为 100%。该值属于客户端全局设置，持久化到 `config/areamusic-client.toml`，不随服务端或存档同步。

最终播放增益为：

```text
Minecraft 主音量 × AreaMusic 独立音量
```

因此原版“音乐”滑块设为 0% 时 AreaMusic 仍正常播放，而主音量设为 0% 时 AreaMusic 静音。滑块通过 Forge 的声音设置界面初始化事件加入现有 `OptionsList`；优先使用原版“语音/旁白”右侧的空单元格，如果该位置已被其他模组占用，则追加独立行以避免覆盖第三方控件。实现不扩展固定的 `SoundSource` 枚举，也不把独立 Java Sound 混音器伪装成原版声音引擎分类。

实际暂停游戏时暂停音频行且保留播放位置；继续游戏时恢复。客户端登出、世界卸载或游戏关闭时停止线程并释放音频行与文件句柄。

## 转换状态规则

- 无区域进入区域：新音轨从 0 淡入目标音量。
- 区域进入无区域：当前音轨按旧区域的 `fadeOutMs` 淡出并释放。
- 不同 MusicID 的区域切换：旧音轨淡出的同时新音轨淡入。
- 相同 MusicID 的区域切换：保持解码位置和循环状态，只平滑调整音量；不重新打开文件。
- 淡化过程中再次切换：保留当前可听音轨的即时音量作为新淡出的起点，启动目标音轨；已经不可听的音轨立即释放，避免点击声与无界音轨增长。
- 非循环音轨到达结尾后保持静音，直到玩家离开该区域并再次进入。

客户端找不到 MusicID、文件损坏或音频设备不可用时，淡出旧音乐并保持静音；聊天栏仅对同一错误提示一次，同时将完整原因写入日志。下一次成功重载会清除提示去重状态并允许重试。

## 并发与性能

- 服务端玩家判定只读取不可变区域快照。
- 磁盘扫描、JSON 解析和音频解码不阻塞游戏主线程。
- 客户端控制器通过有界命令队列与音频线程通信，最新区域状态可以合并旧的未处理状态。
- 音频使用固定大小 PCM 缓冲；大文件不会造成与文件长度成比例的内存占用。
- 所有路径在使用前规范化并验证仍位于对应根目录内。

## 测试策略

不依赖 Minecraft 或真实音频设备的核心逻辑放入可单元测试的 Java 类，并为输出设备提供测试替身。

自动测试覆盖：

- MusicID 路径规范化、扩展名过滤和大小写冲突；
- 区域边界包含、跨维度隔离、优先级和稳定兜底排序；
- JSON 往返、默认值、非法字段及失败重载保留旧快照；
- 淡入、淡出、交叉淡化、同 MusicID 连续播放和快速重复切换；
- 循环与单次播放结束行为；
- 音量乘法、PCM 饱和和命令队列合并；
- AreaMusic 独立音量的默认值、范围、配置写回以及最终增益不依赖原版音乐音量。

Forge 集成验证覆盖命令注册、权限、坐标解析、MusicID 补全、数据包编解码、登录同步、重载同步和专用服务端类加载安全。最终运行 `test`、`compileJava`、`build`，并用开发客户端手动验证 OGG、MP3、WAV、FLAC 的播放及两个相邻区域的交叉淡化。

## 验收标准

1. 新安装首次启动后，服务端与客户端均自动创建 `AreaMusic` 目录。
2. 放入音频并执行 `/areamusic reload` 后，MusicID 立即出现在 `create` 命令补全中。
3. `create` 生成当前存档独立的可读 JSON，并立即生效。
4. 玩家进入区域后音乐按设置播放和循环；离开时在默认 2 秒内平滑淡出。
5. 玩家直接进入不同音乐的区域时，两首音乐同步交叉淡化。
6. 重叠区域按 priority、体积、ID 的顺序稳定选择。
7. 手动编辑有效 JSON 后重载生效；无效 JSON 不破坏上一份运行配置。
8. 多人客户端缺少音频时仅该客户端收到明确错误，服务器与其他玩家不受影响。
