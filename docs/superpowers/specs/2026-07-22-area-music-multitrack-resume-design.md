# AreaMusic 多音轨延迟与重进恢复设计

## 目标

在 Forge 1.20.1 与 NeoForge 1.21.1 中为每个区域增加最多 16 条可并行播放的本地音轨。每条音轨可以在 JSON 中配置进入区域后的启动延迟、音量、循环和淡化参数。区域还可以通过 `resumeOnReenter` 决定玩家离开后再次进入时，是从头开始，还是恢复此前冻结的区域时间线。

同时将游戏根目录下自动生成的音乐目录从 `AreaMusic` 统一修正为全小写 `areamusic`，并安全迁移已有大写目录。

本次变更必须保留现有区域优先级、跨区域淡化、独立音量、格式支持、存档隔离、原子重载和客户端本地文件模型。

## 已确认行为

- 到达各自延迟时间的音轨会并行叠加，不按列表顺序等待上一条结束。
- `delaySeconds` 默认是 `0`，即进入区域后立即播放。
- `resumeOnReenter` 默认是 `false`。
- `resumeOnReenter: true` 时，离开会冻结区域时间线；重进后恢复未完成延迟和各音轨播放位置。
- Forge 1.20.1 与 NeoForge 1.21.1 使用相同 JSON 格式和核心行为。
- 新安装只创建 `<gameDir>/areamusic`，不再生成任何带大写字母的音乐目录。

## JSON 模式

### schemaVersion 2

新版区域文件使用以下结构：

```json
{
  "schemaVersion": 2,
  "dimension": "minecraft:overworld",
  "pos1": { "x": 0, "y": 64, "z": 0 },
  "pos2": { "x": 20, "y": 80, "z": 20 },
  "tracks": [
    {
      "musicId": "ambient.ogg",
      "delaySeconds": 0,
      "volume": 1.0,
      "loop": true,
      "fadeInMs": 2000,
      "fadeOutMs": 2000
    },
    {
      "musicId": "voice.mp3",
      "delaySeconds": 5,
      "volume": 0.8,
      "loop": false,
      "fadeInMs": 0,
      "fadeOutMs": 1000
    }
  ],
  "resumeOnReenter": false,
  "priority": 0
}
```

根对象规则：

- `schemaVersion` 必须为 `2`。
- `dimension`、`pos1` 和 `pos2` 保持现有含义与验证规则。
- `tracks` 必须包含 1 到 16 个对象。
- `resumeOnReenter` 可省略，默认 `false`。
- `priority` 可省略，默认 `0`。
- v2 不再接受根级 `musicId`、`volume`、`loop`、`fadeInMs` 或 `fadeOutMs`，避免一份配置同时出现两套含义。
- 未知字段继续被拒绝。

每条音轨规则：

- `musicId` 必填且不能为空，继续使用包含扩展名、区分大小写的相对路径。
- `delaySeconds` 是非负 32 位整数，可省略，默认 `0`。
- `volume` 范围为 `0.0` 到 `1.0`，可省略，默认 `1.0`。
- `loop` 可省略，默认 `true`。
- `fadeInMs` 和 `fadeOutMs` 范围仍为 `0` 到 `60000`，可省略，默认 `2000`。
- 同一区域允许重复 MusicID。运行时以 JSON 列表索引区分音轨，因此同一个文件可以在不同延迟点重叠播放。
- 列表顺序不决定串行播放，只提供稳定的音轨身份和确定性网络编码顺序。

### schemaVersion 1 兼容

新版模组继续读取现有 v1 文件。v1 根级播放字段在内存中映射为一条音轨：

```text
musicId    -> track.musicId
volume     -> track.volume
loop       -> track.loop
fadeInMs   -> track.fadeInMs
fadeOutMs  -> track.fadeOutMs
              track.delaySeconds = 0
              resumeOnReenter = false
```

读取 v1 不会自动改写磁盘文件。`/areamusic create` 改为生成 v2 单音轨文件，后续可以由管理员直接增加 `tracks` 条目。兼容方向是“两个新版分支都能读取 v1 和 v2”；已经发布的旧模组版本不保证读取 v2。

## 领域模型与职责

### AreaTrackDefinition

新增不可变音轨定义，保存 MusicID、延迟秒数、音量、循环、淡入和淡出。它独立完成单条音轨的范围与空值验证。

### AreaDefinition

区域对象保存不可变音轨列表及 `resumeOnReenter`，不再直接保存单个 MusicID 或根级播放参数。区域 ID、维度、边界、优先级、体积计算和包含判定保持不变。

### AreaJsonCodec 与 AreaStorage

JSON 编解码器显式区分 v1 和 v2，并继续拒绝未知字段。存储层验证每条音轨的 MusicID 都存在于候选服务端音乐库。任一文件或任一音轨无效时，整个候选区域快照失败，当前运行快照保持不变。

### PlaybackState 与网络

播放状态保存区域 ID、不可变音轨列表和 `resumeOnReenter`。停止状态不携带占位音轨。网络编解码必须先验证音轨数量，再逐条编码 MusicID、延迟和播放参数。

Forge `SimpleChannel` 协议版本随不兼容的数据包结构升级。NeoForge 自定义载荷采用相同字段顺序、长度限制和数值验证。音频字节仍不进入网络。

### AreaPlaybackTimeline

新增独立、可单元测试的时间线组件，负责：

- 将秒延迟安全换算为音频帧；
- 记录尚未到期音轨的剩余延迟；
- 记录已启动音轨在当前文件循环中的 PCM 帧游标；
- 记录非循环音轨是否已经完成；
- 导出和恢复不可变暂停快照；
- 在配置版本变化时拒绝使用旧快照。

时间线不访问 Minecraft、网络或文件系统。`PcmMixerEngine` 继续负责解码流、淡化、并行混音和饱和输出，不承担服务端判定或 JSON 解析。

## 服务端数据流

1. 音乐库和区域 JSON 在后台构造候选快照。
2. `AreaStorage` 验证区域内的全部 MusicID。
3. 成功后在服务器线程原子替换音乐库和区域列表，并递增配置版本。
4. `AreaResolver` 继续只选择一个有效区域，优先级、体积和 ID 兜底规则不变。
5. `PlayerAreaTracker` 只在有效区域或其完整播放参数变化时发送状态。
6. 服务端不保存客户端音频进度，也不持续发送计时包；每位客户端独立运行同一份区域时间线。

## 客户端调度与混音

### 进入区域

客户端收到新区域状态时创建该区域时间线，或在快照版本与配置完全匹配时恢复它。延迟从状态生效时开始计算。到达 `delaySeconds` 的音轨立即打开本地文件并按自身 `fadeInMs` 淡入。多个同刻到期的音轨在同一音频块内启动并并行混音。

延迟以 44.1 kHz 音频帧时钟推进，而不是按渲染帧率或客户端 tick 计数。Minecraft 实际暂停、音频设备不可用或区域时间线被冻结时，延迟和播放游标都不推进。

### 离开区域且不恢复

`resumeOnReenter: false` 时，所有已启动音轨按各自 `fadeOutMs` 淡出，未到期音轨立即取消。淡出完成后关闭解码流并删除时间线。再次进入从第 0 秒创建全新时间线，包括已经完成的非循环音轨。

### 离开区域且恢复

`resumeOnReenter: true` 时：

- 离开事件立即冻结尚未到期音轨的剩余延迟；离开淡出时间不计入这些延迟。
- 已启动音轨继续读取足够的 PCM 以完成各自淡出，随后保存淡出结束位置的帧游标并关闭解码流。
- 非循环音轨的已完成状态进入快照，重进后保持静音。
- 循环音轨只保存当前循环内的游标，不需要从文件开头重放所有历史循环。
- 如果淡出尚未结束就重新进入同一区域，直接复用仍打开的解码流并反向淡入，避免不必要的重建。

恢复时在后台重新打开所需文件，并跳过到已保存的 PCM 帧位置；准备完成后再淡入，不阻塞游戏主线程或其他正在播放的音轨。某一音轨恢复失败只会跳过该音轨。

暂停快照由客户端按“配置版本 + 区域 ID”保存。成功区域重载、断线或游戏关闭时清除全部快照；失败重载不会清除当前有效快照。恢复状态不写入磁盘，因此不跨客户端重启或重新连接持久化。

### 区域切换

不同区域继续同步交叉淡化：旧区域音轨淡出的同时，新区域中已经到期的音轨淡入。目标区域延迟从目标状态生效时开始。

为保留现有同 MusicID 连续行为，目标区域中延迟为 0 的音轨可以按“MusicID + 该 MusicID 在列表中的出现序号”与旧区域音轨匹配。匹配成功且解码状态兼容时沿用现有流，并平滑更新循环、音量和淡化目标；延迟大于 0 的目标音轨不会提前沿用旧流。

## 小写音乐目录

新增共享的音乐目录解析组件，服务端与客户端都只请求规范路径 `<gameDir>/areamusic`。它按以下顺序处理：

1. 两个名称都不存在时，创建小写 `areamusic`。
2. 只存在小写目录时，直接使用。
3. 只存在旧大写 `AreaMusic` 时，将其重命名为小写。
4. 在大小写不敏感文件系统上，若两个 Path 指向同一目录，则通过同级唯一临时名称完成仅大小写重命名。
5. 如果两个名称同时存在且实际指向不同目录，则拒绝扫描并报告冲突，不合并、不覆盖也不删除文件。

迁移入口在同一进程内串行化，并能安全处理集成服务器与客户端几乎同时初始化的情况。迁移失败保留原目录不变。代码、日志、文档、测试夹具与手动验证路径都改用小写名称；`config/areamusic` 已经是小写，无需迁移。

## 失败隔离

- 服务端候选音乐库缺少任一配置 MusicID 时，整个重载失败并保留旧快照。
- 客户端缺少或无法解码某一音轨时，仅该音轨静音；同区域其他音轨继续播放。
- 客户端错误继续按错误类型与 MusicID 去重，完整异常写日志，玩家只看到本地化消息。
- 恢复游标重建失败时，仅删除对应音轨的恢复状态。
- 音频设备错误继续使用现有退避重试；设备不可用期间区域时间线暂停，恢复后不会瞬间跳过延迟或内容。
- 目录迁移失败或大小写目录冲突时不修改任何音频文件，并通过现有扫描失败路径提示客户端或重载命令调用者。
- 网络包拒绝 0 条、超过 16 条、过长 MusicID 或非法数值，避免恶意或损坏载荷扩大资源使用。

## 双版本交付策略

先从最新 `forge-1.20.1` 基线完成领域模型、JSON、目录、时间线和混音器的测试驱动实现，再同步 loader-independent 提交到 `neoforge-1.21.1`。两个分支只在构建、事件、配置注册和网络载荷 API 上保留必要差异。

两个版本必须生成各自现有命名规则的完整 JAR，并读取相同的 v1/v2 区域文件和小写音乐目录。现有 Forge 工作树中的无关本地修改不得被覆盖或混入本功能提交。

## 测试策略

### 领域与 JSON

- 音轨默认值、边界值、空 MusicID、非法音量、非法延迟和非法淡化。
- v1 单音轨兼容映射。
- v2 完整往返、缺省字段、1 条和 16 条边界、空列表、17 条音轨及未知字段。
- 重复 MusicID 保持列表身份和顺序。
- 存储层验证列表内每个 MusicID，并在任一失败时拒绝整个加载。

### 网络与服务端

- Forge 和 NeoForge 的播放状态往返测试包含多音轨、延迟和恢复字段。
- 停止状态不编码音轨负载。
- 玩家在同一区域移动时不重复发包；配置版本变化时重新发送完整状态。
- 命令创建 v2 单音轨 JSON，并保持现有权限、坐标和补全行为。

### 时间线与音频

- 延迟 0 立即启动，不同延迟依次到期，同一时刻的多条音轨并行启动。
- 多轨 PCM 正确相加并饱和，每条音轨独立应用音量、循环和淡化。
- Minecraft 暂停和设备失败冻结时间线。
- `resumeOnReenter: false` 重进完全重置。
- `resumeOnReenter: true` 恢复剩余延迟、当前循环游标和非循环完成状态。
- 快速离开重进复用仍在淡出的流。
- 不同区域交叉淡化以及延迟 0 的同 MusicID 连续播放。
- 单条音轨缺失、损坏或恢复失败时其他音轨继续输出。
- MP3、OGG、WAV 和 FLAC 保持原采样率修复及零长度读取修复。

### 目录与集成

- 无目录时只创建小写目录。
- 旧大写目录迁移后文件完整保留。
- 通过临时中间名验证 Windows 仅大小写重命名逻辑。
- 两个独立目录并存时拒绝迁移且不修改内容。
- Forge 使用 Java 17 运行完整单元测试、构建、重混淆、打包和 GameTest。
- NeoForge 使用 Java 21 运行完整单元测试、构建、打包和 GameTest。
- 两个真实开发客户端分别验证 MP3、OGG、WAV 和 FLAC 的多轨延迟、离开淡出、重进恢复和小写目录。

## 验收标准

1. 新安装只生成 `<gameDir>/areamusic`。
2. 只有旧 `AreaMusic` 时，启动后安全迁移为 `areamusic` 且音频文件不丢失。
3. Forge 1.20.1 和 NeoForge 1.21.1 都能读取同一份 v1 或 v2 JSON。
4. 区域内 1 到 16 条音轨在各自延迟到期后并行播放。
5. `resumeOnReenter: false` 时每次重进从头开始。
6. `resumeOnReenter: true` 时恢复剩余延迟、循环内播放位置和非循环完成状态。
7. 单条客户端音轨失败不会停止同区域其他音轨。
8. 区域优先级、相邻区域交叉淡化、独立音量、暂停、重载原子性和四种音频格式不回归。
9. 两个版本的自动测试、构建、打包与 GameTest 均通过，最终工作树仅包含本功能相关改动。

## 不在范围内

- 在游戏内编辑多音轨列表或恢复字段。
- 将恢复快照写入磁盘，或跨断线、重启和成功重载保持播放进度。
- 向客户端传输音频文件。
- 改变区域重叠优先级或每位玩家只选一个有效区域的规则。
- 新增 Fabric 或其他 Minecraft 版本。
